## 1. 背景与目标

### 现状

机器上现存一套旧方案，位于 `C:\Users\ch\auto-shutdown\`：

| 文件 | 作用 |
|---|---|
| `shutdown-confirm.ps1` | `shutdown /s /t 20` 排程 + WScript 弹窗 10 秒，点取消则 `shutdown /a` |
| `register-task.ps1` | 注册计划任务 `AutoShutdown_2AM`，每天 02:00 触发 |

### 旧方案的痛点

1. 关机时间硬编码在脚本里，改时间要改文件并重新注册计划任务
2. 没有任何界面，只能靠记事本编辑 `.ps1`
3. 决策窗口只有 10 秒，人在电脑前也可能来不及点
4. 看不到当前状态（是否已排定、还剩多久）
5. 只支持"每天 02:00"一种模式

### 目标

做一个带图形界面的定时关机应用，支持自由设定关机时刻与随时取消，界面有一定美化，替代旧方案。

## 3. 架构

### 3.1 方案选型

定时由谁守着，有三个候选：

| 方案 | 说明 | 结论 |
|---|---|---|
| **A. 应用常驻托盘** | 应用启动后驻留系统托盘，所有定时在应用进程内运行；配合开机自启，重启后自动恢复每日规则 | **采用** |
| B. 计划任务驱动 | 每次设定"每天重复"就注册一条 Windows 计划任务，到点由系统唤起应用弹窗 | 否 |
| C. A + B 双保险 | 常驻托盘，同时写计划任务兜底 | 否 |

**选择 A 的理由**：单一状态源（配置只存在应用里一份），UI 全流程一致，没有计划任务残留问题。

**B 被否的理由**：状态分裂成两份（应用内存 + 系统任务表），两者不一致时排查成本高，卸载时需额外清理残留任务。

**C 被否的理由**：对个人工具而言是过度设计。

**A 的已知代价**：依赖"开机自启"（F12 已批准），"每天重复"才能在重启后继续生效。手动退出应用时规则会暂时失效——退出前会弹确认提示。

### 3.2 可靠性设计（关键）

沿用旧脚本那套经过验证的模式，但按动作类型区分：

**关机 / 重启 —— 系统级排程 + 应用弹窗（双保险）**

1. 到点先调用 `shutdown /s /t N`（重启为 `/r`），把排程交给操作系统
2. 再弹出应用确认窗，展示 N 秒倒计时
3. 用户点"取消关机" → `shutdown /a` 中止排程
4. 用户点"立即执行" → `shutdown /s /t 0` 立刻执行
5. 用户无操作 → 不做任何事，系统按自己的排程关机

这样设计的价值：**即使应用卡死或崩溃，系统排程依然会执行关机**，不会出现"以为设了结果没关"。

**睡眠 / 休眠 / 注销 —— 应用内计时（无系统兜底）**

`shutdown /a` 只能取消由 `shutdown` 命令排定的关机与重启，**睡眠、休眠、注销没有对应的系统级排程接口**，无法预先交给操作系统。

因此这三种动作改为：确认窗倒计时结束后，由应用直接执行。代价是应用若在倒计时期间崩溃，动作不会发生（偏安全的方向，不会误操作）。

### 3.3 动作实现对照

| 动作 | 触发命令 | 可否用 `shutdown /a` 取消 |
|---|---|---|
| 关机 | `shutdown /s /t N` | ✅ |
| 重启 | `shutdown /r /t N` | ✅ |
| 睡眠 | Win32 `SetSuspendState(0, ...)` | ❌ 仅应用内取消 |
| 休眠 | Win32 `SetSuspendState(1, ...)` | ❌ 仅应用内取消 |
| 注销 | `shutdown /l` | ❌ 仅应用内取消 |

> **实现注意**：`rundll32.exe powrprof.dll,SetSuspendState` 这种常见写法在系统启用休眠时会表现为休眠而非睡眠，无法可靠区分。实现时须通过 `ctypes` 直接调用 `powrprof.dll` 的 `SetSuspendState` API，并先查询休眠是否启用，以正确区分睡眠与休眠。

### 3.4 模块划分

单一职责，各自可独立理解与测试：

```
main.py              入口：单实例检测、命令行参数解析、dry-run 开关
app/window.py        主窗口：状态卡片、各类定时控件、动作与选项、取消按钮
app/confirm.py       关机确认窗：大号倒计时数字、环形进度、取消/立即执行
app/scheduler.py     定时调度：下次触发时刻计算、QTimer 驱动、触发回调
app/power.py         电源动作封装：arm/abort/execute_now，唯一调用系统命令的地方
app/config.py        配置读写：JSON 序列化、默认值、原子写入
app/theme.py         两套主题的样式表与配色常量
app/autostart.py     开机自启的注册与注销
assets/icon.ico      应用与托盘图标
启动.bat             无控制台窗口启动
config.json          运行时生成的用户配置
run.log              运行时生成的操作日志
```

各模块职责边界：

| 模块 | 做什么 | 依赖 |
|---|---|---|
| `scheduler.py` | 回答"下次该在什么时刻触发"，到点回调。不碰系统命令 | `config` |
| `power.py` | 唯一执行系统电源命令的地方，含 dry-run 分支 | 无 |
| `config.py` | 配置的读写与校验，不关心业务语义 | 无 |
| `autostart.py` | 在启动文件夹增删快捷方式 | 无 |
| `window.py` / `confirm.py` | 展示与收集用户输入，通过信号调用 scheduler/power | `scheduler`, `power`, `config`, `theme` |

**`power.py` 是唯一允许调用 `shutdown.exe` 的模块**——这保证 dry-run 开关只需在一处生效，调试期绝不会误关机。

## 5. 数据结构

`config.json`：

```json
{
  "version": 1,
  "action": "shutdown",
  "force": false,
  "grace_seconds": 60,
  "autostart": true,
  "theme": "dark",
  "dry_run": false,
  "daily": {
    "enabled": false,
    "time": "23:30"
  },
  "oneoff": {
    "enabled": false,
    "target": "2026-09-15T23:30:00",
    "label": "今晚 23:30"
  }
}
```

字段说明：

| 字段 | 类型 | 取值范围 | 说明 |
|---|---|---|---|
| `action` | string | `shutdown` / `restart` / `sleep` / `hibernate` / `logoff` | 到点执行的动作 |
| `force` | bool | — | 是否强制结束未响应程序 |
| `grace_seconds` | int | 10–300 | 确认窗倒计时秒数 |
| `autostart` | bool | — | 是否开机自启 |
| `theme` | string | `dark` / `light` | 界面主题 |
| `dry_run` | bool | — | 调试开关，`true` 时所有电源命令只写日志不执行 |
| `daily.enabled` | bool | — | 每天重复是否启用 |
| `daily.time` | string | `HH:MM` | 每天触发时刻 |
| `oneoff.enabled` | bool | — | 一次性定时是否已排定 |
| `oneoff.target` | string | ISO 8601 本地时间 | 一次性触发的绝对时刻 |

`oneoff` 与 `daily` 可同时启用，两者独立触发，各自弹确认窗。

配置写入采用**临时文件 + 替换**的原子写法，避免写入过程中断电导致配置损坏。

## 6. 边界情况

| 场景 | 处理 |
|---|---|
| 应用启动时已存在另一实例 | 单实例锁检测到后，激活已有窗口并退出本次启动 |
| 设定的一次性时刻已过去 | 拒绝设定并提示；界面默认值永远取未来时刻 |
| 每天重复的时刻今天已过 | 自动顺延到明天，状态卡片显示"明天 23:30" |
| 用户手动退出应用且"每天重复"处于启用状态 | 弹确认提示"退出后每天重复将失效，是否继续" |
| 确认窗期间用户又设了新的定时 | 旧的倒计时窗口关闭；若旧排程已通过 `shutdown` 命令下发给系统，须先 `shutdown /a` 撤销再下发新排程 |
| 睡眠/休眠动作在倒计时期间应用崩溃 | 动作不执行（安全方向），日志记录异常 |
| 系统时间被修改 / 跨时区 | 每次触发后重新计算下次时刻，不缓存长时间的绝对时间差 |
| 宽限期设置为极短值 | 下限锁定 10 秒 |
| 配置文件损坏或字段非法 | 回退到默认值并备份损坏文件，不阻断启动 |
| 启动文件夹快捷方式被用户手动删除 | 下次启动时按 `autostart` 配置重新写回 |

## 7. 测试策略

### 7.1 单元测试（pytest）

针对纯逻辑模块，不涉及 GUI 与系统命令：

- `scheduler.py`：下次触发时刻计算——今天未到 / 今天已过 / 跨天 / 闰日边界
- `config.py`：默认值填充、缺失字段容错、非法值回退、原子写入后文件可读回

### 7.2 dry-run 验证（安全关键）

`--dry-run` 模式下 `power.py` 把所有系统命令替换为日志输出，形如：

```
[DRY-RUN] 将执行: shutdown /s /t 60
[DRY-RUN] 将执行: shutdown /a
```

**开发调试全程开启 dry-run，任何涉及真实关机的验证须用户在场并明确同意。**

### 7.3 手动验收清单

1. 快速定时 30 分钟 → 状态卡片显示剩余时间并逐秒递减
2. 确认窗在到点时弹出，倒计时归零前点"取消关机" → 排程被中止，状态回到未排定
3. 点右上角 ✕ → 同样中止关机
4. 关闭主窗口 → 应用仍在托盘中运行，悬停显示剩余时间
5. 托盘右键"取消关机" → 生效
6. 切换暗色/亮色主题 → 界面即时变化，重启应用后保持
7. 勾选开机自启 → 启动文件夹出现快捷方式；重启系统后应用自动运行
8. 设定每天重复 → 重启系统后应用自动启动且规则仍在
9. 设定一个 1 分钟后的定时 → 真实执行一次关机（用户在场确认）
